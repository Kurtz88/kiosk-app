# Windows에서 키오스크 자동 실행

`bat\start_kiosk.bat`을 **로그인한 뒤** 자동으로 돌리는 방법입니다.

### “윈도우만 켜면” 바로 돌아가게 하려면

- **시작 프로그램**·**로그온 작업**(아래 방법 1·1b)은 모두 **사용자가 Windows에 로그인한 다음**에만 실행됩니다. 로그인 화면에서 멈춰 있으면 실행되지 않습니다.
- 키오스크 PC처럼 **전원만 넣으면 곧바로 키오스크가 떠야** 한다면 **자동 로그인**을 켜 두는 것이 일반적입니다. (설정 → 계정 → 로그인 옵션, 또는 `netplwiz`에서 “사용자 이름과 암호를 입력해야 합니다” 해제)
- 자동 로그인이 되면, 그 다음에 시작 프로그램 또는 로그온 작업이 실행되어 `start_kiosk.bat`이 돌아갑니다.

## 방법 1: 시작 프로그램 (가장 간단)

1. 프로젝트 폴더에서 **`bat\kiosk-tools.bat`** 을 실행한 뒤 메뉴 **3** (시작 프로그램 바로가기)을 선택합니다. (명령줄: `kiosk-tools.bat 3`)
2. 다음 로그인부터 `bat\start_kiosk.bat`이 자동 실행됩니다.

**해제:** `Win` + `R` → `shell:startup` 입력 → `RestaurantKiosk` 바로가기 삭제.

## 방법 1b: 작업 스케줄러 자동 등록 (로그온 후, 권장에 가깝게)

시작 프로그램과 비슷하게 **로그인 직후** 실행되지만, 작업 스케줄러로 등록되어 지연·재시도 동작을 쓰기 쉽습니다.

1. **`bat\kiosk-tools.bat`** 실행 → 메뉴 **4** (또는 `kiosk-tools.bat 4`).
2. 기본으로 **현재 사용자 로그온 후 약 20초 뒤**에 `bat\start_kiosk.bat nopause`가 실행되도록 `RestaurantKioskLogon` 작업이 등록됩니다.

**해제:** `kiosk-tools.bat` 메뉴 **5** (또는 `kiosk-tools.bat 5`), 또는 작업 스케줄러에서 `RestaurantKioskLogon` 삭제.

**주의:** 시작 프로그램 바로가기(방법 1)와 **동시에** 쓰면 `start_kiosk`가 두 번 떠서 Chrome·서버가 중복 실행될 수 있습니다. **둘 중 하나만** 쓰세요.

## 방법 2: 작업 스케줄러 (수동으로 만들 때)

1. `Win` 키 → **작업 스케줄러** 실행.
2. **기본 작업 만들기**  
   - 트리거: **로그온할 때** (또는 **시작할 때** — 로그인 없이 띄우려면 고급 설정 필요)  
   - 동작: **프로그램 시작**  
   - 프로그램: `cmd.exe`  
   - 인수 추가: `/c "경로\bat\start_kiosk.bat" nopause` (자동 실행 시 `pause` 에서 멈추지 않게)  
   - **시작 위치:** 프로젝트 폴더 전체 경로 (예: `D:\kiosk-restaurant-app`)
3. (선택) **지연** 30초 — 네트워크·디스크 준비 후 실행.

## 방법 3: 레지스트리 실행 항목

`Win` + `R` → `regedit`

- 사용자만:  
  `HKEY_CURRENT_USER\Software\Microsoft\Windows\CurrentVersion\Run`  
  문자열 값 추가 → 이름 예: `Kiosk`, 값: `"D:\경로\bat\start_kiosk.bat"` (경로에 공백 있으면 따옴표)

## 키오스크 PC에서 같이 쓰는 설정

- **자동 실행·방화벽·재부팅 등:** `bat\kiosk-tools.bat` 한 파일에서 메뉴로 묶어 두었습니다. (`kiosk-tools.bat help` 로 번호 안내)
- **자동 로그인:** 설정 → 계정 → 로그인 옵션 (또는 `netplwiz`에서 사용자 암호 생략).
- **전원:** 절전·화면 끄기 비활성화.
- **업데이트 후 재부팅:** 업무 시간 외에만 적용되게 조정.

`bat\start_kiosk.bat`은 먼저 프로젝트 루트(`%~dp0..`)로 이동한 뒤, Node 서버는 **제목이 `Kiosk Server` 인 별도 CMD 창**에서 돌게 합니다(런처만 닫아도 서버는 유지). 수동 실행 시 마지막에 `pause`가 있어 안내를 읽을 수 있고, 자동 실행 시에는 **`start_kiosk.bat nopause`** 로 `pause`를 건너뜁니다. 바로가기·작업 스케줄러는 **시작 위치(작업 폴더)를 프로젝트 루트**로 맞추면 됩니다.

## 자동 실행이 안 될 때 (점검 순서)

1. **등록을 했는지**  
   - 시작 프로그램: `bat\kiosk-tools.bat` → **3** (또는 `kiosk-tools.bat 3`)을 한 번 실행해야 `시작 프로그램`에 `RestaurantKiosk` 바로가기가 생깁니다.  
   - 로그온 작업: 같은 도구에서 **4** (`kiosk-tools.bat 4`)를 실행하면 작업 스케줄러에 `RestaurantKioskLogon` 이 생깁니다. 둘 중 **하나만** 쓰는 것이 좋습니다.

2. **“부팅 직후”가 아니라 “로그인 직후”**  
   시작 프로그램 항목은 **Windows에 사용자가 로그인한 뒤**에만 실행됩니다. 전원만 켜고 로그인 화면에서 멈춰 있으면 실행되지 않습니다. 키오스크 PC는 **자동 로그인**을 켜 두는 경우가 많습니다. (설정 → 계정 → 로그인 옵션, 또는 `netplwiz`)

3. **다른 계정으로 로그인**  
   바로가기는 **등록한 그 Windows 사용자**의 시작 폴더에만 들어갑니다. 다른 사용자로 로그인하면 해당 계정에서는 실행되지 않습니다.

4. **바로가기가 있는지**  
   `Win` + `R` → `shell:startup` 입력 → `RestaurantKiosk` 바로가기가 보이는지 확인합니다. 없으면 `kiosk-tools.bat` → **3** 을 다시 실행합니다.

5. **시작 프로그램에서 꺼짐**  
   `Ctrl` + `Shift` + `Esc` → **시작 프로그램** 탭에서 `RestaurantKiosk` 가 **사용 안 함**으로 되어 있지 않은지 확인합니다.

6. **프로젝트 폴더를 옮긴 뒤**  
   폴더 경로가 바뀌면 바로가기가 깨질 수 있습니다. 그때도 `kiosk-tools.bat` → **3** 으로 등록을 새로 하세요.

7. **USB/네트워크 드라이브**  
   프로젝트가 USB나 네트워크 드라이브에만 있고, 로그인 직후에는 아직 연결되지 않으면 `npm` / `node` 가 실패할 수 있습니다. 가능하면 **로컬 디스크**에 두는 것이 안전합니다.
